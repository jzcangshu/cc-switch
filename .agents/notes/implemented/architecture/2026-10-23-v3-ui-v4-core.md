# Agent Note: 复用第三版界面并保留第四版运行时

Status: implemented

## Problem

用户需要第三版的全部界面体验和第四版最新正式内核。第三版与第四版同时存在视觉和业务契约变化，直接替换前端会破坏配置保存、模式语义、技能批量结果和会话内容读取。

## Decision

基线固定为 v4.0.18，视觉参照固定为 v3.20.4。恢复顶部导航、原有设置页签、卡片和单页编辑体验；保留第四版的接口、数据类型、查询缓存、业务钩子和后端。新增功能只增加必要入口与呈现。第四版业务状态和动作保持单一来源，不增加双版本适配后端。

供应商编辑保留编辑投影、基准和冲突策略；模式查看与模式提交分离；会话保留结构化块与分块读取；技能保留含部分失败的返回对象。不复活通用配置片段、费用倍率或已移除的连通性参数。

历史审计：新工作区来自正式标签，无既有 .agents/notes（决策记录）目录；旧二开分支及其笔记属于用户明确放弃的工作，归档后不合入。

设置使用同一个表单实例承载六个旧页签。目录字段只在显式保存时提交；查询刷新采用上一份服务器基线，保留真实本地目录草稿，避免修改其他设置时丢掉草稿。真正离开设置时才确认是否放弃。

提示词复用既有 MarkdownEditor（标记文本编辑器）。只读、主题和无障碍属性采用原位配置更新，保持撤销历史；外部载入内容不应成为用户的一次编辑。预设搜索和分类不登记为未保存编辑，真实字段与预设选择仍登记。

技能发现按卡片行虚拟化，实际测量每行高度；已安装技能与 MCP（模型上下文协议）恢复第三版紧凑列表。会话继续消费第四版结构化内容，在至少 900 像素宽度下显示 320 像素左列表及右阅读区，更窄时依次显示列表与阅读页。

## Alternatives considered

- 整套第三版前端覆盖第四版：旧体验还原最直接，但会让已移除的保存/配置逻辑重新出现并漏读第四版数据，拒绝。
- 只给第四版改色：接线风险最低，但保留侧栏、两步新增与新卡片操作方式，无法满足旧版体验要求，拒绝。
- 第三版界面加全面兼容层：可逐项模拟旧接口，但增加第二套状态和错误恢复语义，长期维护成本与静默错误风险高，拒绝。

## Consequences

第四版许多组件将业务与呈现写在同一文件，需要有选择地恢复布局而不是原样覆盖。旧图标条在新应用数下需验证溢出；返回按钮需维持第四版未保存确认。浏览器模拟只能验证前端交互，真实客户端配置写入要单独用隔离测试验证。

这保留单一业务模型，但后续跟进第四版时仍须逐项合并组件中的新能力，不能整文件覆盖。新能力的聚合配置、富会话阅读、应用安装与账号管理沿用第四版逻辑，使用第三版控件与导航。旧侧栏的今日统计和账号提醒迁到底部状态区，原设置仍有效。

验证以同一正式标签的代码和锁文件为基线。原固定 Rust（内核编译器）1.95 工具链在本机因跨磁盘移动错误无法初始化，使用已安装的 1.96 稳定版完成后端验证与桌面测试构建，不更改仓库工具链声明。完整后端测试为 3869 通过、11 项原有忽略。最终前端检查和构建结果记录在实现计划中。
