# Agent Note: 独立程序必须嵌入界面资源

Status: implemented

## Problem

融合版测试程序在构建后可以生成可执行文件，却从构建机的目录加载界面。目录不可用时显示“未找到文件”，无法启动主界面。前端测试和编译成功都没有发现这个交付缺陷。

Tauri（桌面应用框架）的 frontendDist（界面资源来源）先尝试解析为网址，再尝试目录。构建覆盖配置中的 Windows（视窗系统）盘符绝对路径可以解析为网址，命中“不嵌入资源”的分支。默认配置中的相对目录本来正确，错误来自临时构建覆盖。

## Decision

独立构建使用 scripts/build-standalone.ps1（独立构建脚本），为每次构建建立新的输出目录，并把界面资源来源写成相对于 src-tauri（内核项目目录）的路径。前端使用相对于 src（界面源码目录）的相同相对路径。构建继续通过官方命令执行，不改变第四版内核、依赖或默认配置。

构建脚本在前端或内核失败时停止，成功后复制本次程序并生成摘要。旧输出保留。交付验收必须将程序复制到无法访问源码和界面输出目录的独立系统，观察真实主窗口、导航和托盘页面；仅验证编译或相对引用的网页不算独立程序验收。

现有[融合版架构记录](../architecture/2026-10-23-v3-ui-v4-core.md)保留界面与内核的职责；本记录仅覆盖构建与交付边界。历史检索只命中该架构记录，属于部分重叠，无过时提案。

## Alternatives considered

- 直接使用默认输出目录：配置最简单且默认可以嵌入资源，但前端默认先清空旧构建输出，违反用户的保留文件约定，拒绝。
- 给程序附带界面目录：可以绕过错误页面，但继续依赖外部文件和构建目录语义，不能满足独立可执行文件的交付要求，拒绝。
- 继续用绝对路径：方便将输出放在自动化目录，但盘符会被解释为网址，正是缺陷来源，拒绝。

## Consequences

每次构建保留独立的界面输出、配置、可执行文件和摘要，方便复核与重现，代价是增加磁盘占用。系统沙箱需要另行准备 WebView2（网页显示运行时）；只有环境运行时可用才进行原生界面验收。交付文件仍需验证更新渠道及真实客户端联动，不能把本次启动修复扩大为全部功能已经实测。

## Testing

在同一断网系统沙箱中复现原程序“未找到文件”，随后仅复制修复后的可执行文件。源码和原界面输出目录均不可访问。修正版主界面、六设置页签、明暗主题、技能和协议工具列表以及托盘独立页面正常加载；第二次启动界面正常且保留深色主题。日志中的界面脚本来自程序内部 http://tauri.localhost（本地资源地址）。断网导致的在线模型目录和自动更新失败单独记录。

本轮只修改构建脚本和文档，第四版内核与依赖无差异。独立优化构建、脚本语法、笔记目录和格式检查通过；旧程序失败与新程序成功构成打包回归验证，不把前一轮全量测试计作本轮重新执行。
